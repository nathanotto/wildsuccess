# Wild Success — Operating Principles

> The 12 tenets that shape how Wild Success thinks about itself, its members, and the work the product is in service of. These are not marketing copy. They are operating beliefs that should shape every interaction, every microcopy decision, every interface affordance.

---

1. **Fears of failure are planning constraints.** Fear is information about what to plan around — not a personal flaw to overcome.

2. **Every human wants to contribute and be acknowledged.** Design for visible contribution. Every action a user takes should be legible to them and to the people it affects.

3. **Primary data for truth; grounded assessment for action.** Show the real thing first. Don't summarize, abstract, or score before the user has seen the underlying data.

4. **Repetitions become systems.**
   a. Repeated failure → prevention systems.
   b. Repeated value → solved problem.

5. **People need agency like they need air.** No paternalism. No silent system actions on the user's behalf. The user is always the actor.

6. **Wild Success grows because people experience better value, easier cooperation, and alignment.** Growth is a consequence of these three things — not a goal to optimize directly.

7. **Defective behavior — in the Tit-for-Tat iterated prisoner's dilemma sense — is detected and corrected immediately.** Disputes, broken commitments, and missed expectations are surfaced fast, not buried.

8. **Reputation is the recent accumulation of what other people experience with you.** Reputation is earned in interactions, not declared in profiles. The product reflects this.

9. **We can agree on values but differ on vision (that expresses those values).**
   a. We can agree on vision but differ on plans (to achieve that vision).
       i. We can agree on values, vision, and plans but differ on actions (to implement that plan).

10. **None of those differences below values alignment impair our connection. We each take action according to our lights.** Disagreement on tactics is normal and healthy. The product should make this disagreement productive.

11. **Real-time, trustable data is essential.** Stale, derived, or guessed data corrodes the system. Show the freshness; show the source.

12. **We give each other kind, objective feedback, and we accept it as a gift.** Feedback flows are first-class flows. The product should make giving and receiving feedback feel safe and useful.

---

## How these show up in design

| Principle | Design implication |
| --- | --- |
| 1. Fears as constraints | Surface blockers and friction in plain language; don't hide them under "edit" or "settings." |
| 2. Contribution is visible | Confirmation patterns always include "what changed" and "who will see it." |
| 3. Primary data first | Show the source data before the summary. Aggregates are secondary, not primary. |
| 4. Repetitions become systems | Surface patterns ("you've abandoned this 3 times"); offer to systematize. Never auto-systematize. |
| 5. Agency like air | No background actions without disclosure. Every system effect is attributable to a user action. |
| 6. Growth is consequence | No engagement metrics, streaks, gamification. Value, cooperation, alignment are the signals. |
| 7. Defection corrected fast | Disputed commitments, missed RSVPs, ignored requests get surfaced — not hidden. |
| 8. Reputation from experience | No badges, levels, or scores. Reputation reads from real interactions: completed commitments, value ratings, attendance. |
| 9. Values → vision → plans → actions | UI hierarchy mirrors this: Values (Map) → Outcomes → Activities → Today's list. |
| 10. Differences below values are fine | Allow divergence. Don't force consensus on tactics. Plan module supports multiple Courses of Action. |
| 11. Real-time data | Show timestamps, "saving…" states, last-updated stamps. Never claim freshness that isn't there. |
| 12. Feedback as gift | Meeting feedback (1–10 + most-valuable member) is built into the meeting close flow. Confirmations of commitments invite real "did this happen?" answers, not pro-forma checkboxes. |

## Voice consequences

These principles dictate the voice of the product:

- **Confirmations name the consequence.** "Meeting scheduled. RSVPs will go out to 7 members." — not "Success!"
- **Errors name the constraint.** "This member is already in 2 chapters (the limit)." — not "Cannot perform action."
- **Empty states name the actor.** "No commitments yet. Add one when you're at your next meeting." — not "Nothing here."
- **Decisions are owned, never softened.** "Approve" / "Reject" / "Decline" — not "Maybe later" or "Skip for now."
- **Time is honest.** "2 minutes ago" / "Saving…" / "Last meeting: Tue, Apr 16." Never "recently" or "a while back."
